# Codex LAN

**Your Codex, shared with your team.**

Codex LAN turns one Linux host's Codex into a browser workspace for approved coworkers on a trusted office network. People use the shared host from their own computers, with separate conversations, per-person access and usage controls, and native Connectors for working on their own files. The host's Codex sign-in stays on the host—not in a shared password or a public repository.

**The main idea:** make Codex a practical team resource at work, not just a tool on one person's machine.

Product vision and direction: **Hamid**. Implementation and engineering collaboration: **Codex**.

## What makes it worth opening?

- **Share the assistant, not the credentials.** A host provides Codex access; an administrator approves coworkers, assigns limits, and can revoke access. Teammates connect through their browsers.
- **Parallel work, separate controls.** Independent conversations with model, thinking, speed, workspace, and execution-enforced read-only settings; steer a running response with Send update.
- **Two ways to go deeper.** Select a passage: open an independent, resizable Side thread—or a floating More details explanation. Both survive reloads.
- **Keep the trail.** Saved drafts, durable public Progress logs, tool Activity, and available Prepared context—not hidden reasoning.
- **Usage with context.** Per-response token reports, estimated account-share usage, and a dashboard for the pool of finite allocations.
- **Built for actual attention.** Stable pins, recent-message ordering, automatic room titles, owner-specific unread marks, and focus-aware completion notifications.
- **Polish without noise.** Persian/RTL, bundled Vazir, Markdown and math, file attachments, Cosmic and editor-inspired themes, and expressive send effects with reduced-motion support.

## Hamid's product-lead scorecard

Editorial impact levels from this collaboration, not personality scores: **±1 mild · ±2 meaningful · ±3 defining**. No overall score.

| Observed strength or weakness | Level | What showed it |
| --- | --- | --- |
| Product instinct | **+3** | Turned a personal assistant into a shared workplace resource, with separate rooms, understandable allocations, and attention-aware notifications. |
| Acceptance standards | **+3** | Screenshots and repeated “still wrong” feedback caught issues a passing test alone missed. |
| Ownership and taste | **+2** | Clear privacy boundaries, portability requirements, and willingness to remove excessive animation. |
| Expanding scope | **−2** | Multiple new directions sometimes competed with stabilization. Smaller, ranked releases would help. |
| Compressed timelines | **−2** | Frequent urgency creates verification pressure. Protected test and acceptance checkpoints would help. |

These risks do **not** make Hamid responsible for service crashes; implementation failures belong to the engineering process, including Codex's choices.

**The takeaway:** Hamid's high bar gives the product its character. The next improvement is smaller release scopes—not fewer ideas.

Codex's own additions include the keyboard Quick Switcher, local draft-size meter, per-response context receipts, and guarded deployment mechanisms.

For authorized, trusted coworkers—not public hosting or isolation between untrusted tenants. Follow your organization's and provider's access rules. Usage percentages are estimates, not official per-user billing. Runtime chats and credentials stay outside source exports. This project is independent of OpenAI.
