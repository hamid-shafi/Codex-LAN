Workspace owner

Start with one command.

Extract or clone the project. In its folder, as your normal Linux user:

bash setup.sh

Choose Host. The menu also offers prerequisite checks and optional Python/OS and official Codex helpers. It asks before installing.

Finish in Administration → Host setup: configure HTTPS, prepare Connector downloads, and choose whether to keep the laptop awake.

What you need

Linux, Python 3.10+ with venv, a systemd user session, OpenSSL, and the official standalone Codex signed in on this host. First-time downloads need Internet.

The setup helper can guide you through these. It does not overwrite a running installation. Don't run the app as root.

Teammate

A browser first. Local tools next.

  1. Get the HTTPS address and public CA certificate from your administrator. Verify its fingerprint through a trusted channel before trusting it.
  2. Open the address, choose Connect a new computer, enter your computer name, and choose Request access. Send the verification code to the administrator.
  3. Stay in that browser profile until approved. Then choose Connector → Download one-step setup.
  4. Run your private installer as your normal Linux user, or inside WSL2 on Windows. Pairing expires; download a new installer if needed. Never share it with someone else.

You don't need the host's OpenAI password or your own Codex installation. The Connector supplies its runtime bundle; Linux/Python and OS service prerequisites still need to exist. Full-access tools run under your own OS user.

Windows / WSL2

Two stages, clearly separated.

1. Join in Windows

Extract the whole source ZIP. Double-click setup\windows\start.cmd for this guide and read-only checks. No Python or PowerShell script-policy change needed.

Chrome or Edge can request access immediately. A relay also needs Windows OpenSSH Client.

2. Enable local file tools

The Connector currently runs in WSL2 Ubuntu on x86_64, with Python 3.10–3.14 and working systemd user services. Not native Windows, Git Bash, or ARM64.

Prepare WSL with your Windows administrator if required. No automatic WSL shutdown, certificate trust, or security-policy changes are performed by the starter.

Windows, certificates, WSL, and troubleshooting →
PowerShell says scripts are disabled?

The start.cmd guide still works. The Windows guide includes a native SSH command that does not run a PowerShell script. Don't disable execution policy globally or bypass your organization's restrictions. WSL access errors and SSH authorization are separate issues.

Outside the office LAN

A bridge, not another database.

Your browser + Connector → Restricted SSH relay → The host laptop

The administrator sets up restricted SSH accounts and the laptop's publisher tunnel first. Only SSH is exposed publicly; the forwarded application port stays on relay loopback.

bash setup.sh relay YOUR_USER@YOUR_RELAY

Replace the placeholder with your administrator's login. Verify the SSH host key and laptop CA separately. Open https://127.0.0.2:8767 and keep the tunnel open.

A successful tunnel can be silent. “Permission denied” is an authentication failure. SSH access is not app approval. For Windows and WSL, verify the route in both environments.

The laptop must stay powered, awake, and online. A relay cannot keep the app running while it sleeps.
